# SecondSelf — Engineering & Code Conventions

## 1. Overview & Core Philosophy

This document defines the strict engineering standards, coding guidelines, schema contracts, and repository conventions for the **SecondSelf** project. Every contributor and autonomous agent must adhere to these conventions to ensure architectural integrity, seamless GitOps automation, and full compliance with Vercel serverless deployment constraints.

### Core Architectural Axioms
1. **The Dual-Plane Separation Rule:** Heavy ML dependencies (`torch`, `sentence-transformers`, `scikit-learn`, `trafilatura`) must **never** be placed in `requirements.txt`. They belong exclusively in `requirements-dev.txt`.
2. **Stateless Serverless Rule:** All code inside `api/` must treat the filesystem as strictly read-only and ephemeral. No file writes or persistent mutations are permitted in serverless handlers.
3. **Deterministic Local Pipeline:** All knowledge generation (`raw/` captures, `wiki/` note curation, vector calculation, and `public/` graph exports) happens deterministically in the local build plane.
4. **Zero-Secret Leakage:** API keys (such as `GROQ_API_KEY`) must never be hardcoded, logged, or committed to Git.

## 3. Python Coding Standards (Python 3.10+)

### 3.1 Code Style & Formatting
- **Standard:** Follow **PEP 8** strictly.
- **Formatter:** Black with line length limit of **100 characters** (`black --line-length 100 .`).
- **Linter & Import Sorter:** Ruff (`ruff check .`) and isort (`isort --profile black .`).
- **Quote Style:** Double quotes `"` for strings and docstrings; single quotes `'` allowed only when escaping quotes in strings.

### 3.2 Type Annotations
- **Strict Typing:** All function signatures must include comprehensive type annotations for arguments and return values using the `typing` module or native Python 3.10+ union types (`int | None`).
- **Pydantic Models:** Use `pydantic.BaseModel` for complex structured objects (e.g. Raw captures, Classified note schemas, API requests/responses).

    raw_content: str = Field(..., description="Extracted unstructured content")

### 3.3 Error Handling & Logging
- **No Bare Excepts:** Never write `except:` without an exception class. Always catch specific exceptions (`requests.RequestException`, `FileNotFoundError`, `groq.APIError`).
- **Graceful CLI Logging:** For user-facing local scripts (`capture.py`, `classify.py`), use the `rich` library for formatted status, progress bars, and colored diagnostics.
- **Standard Logging for Serverless:** In `api/ask.py`, use Python’s built-in `logging` module with standard formatting so logs appear clearly in Vercel Runtime Logs:
  ```python
  import logging
  logger = logging.getLogger("secondself.ask")
  logger.setLevel(logging.INFO)
  ```

## 4. Data Formats & Schema Contracts

### 4.1 Identifiers & Timestamps
- **Unique Identifier (UUID):** Canonical UUIDv4 string in lowercase: `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`.
- **File Prefix Timestamp:** `YYYYMMDD_HHMMSS` (UTC).
- **Schema Timestamp:** Full ISO-8601 UTC format with trailing `Z`: `2026-11-23T09:15:30.124Z`.

### 4.2 The PARA Category Standard
The category field across all systems must be an exact match to one of the four PARA taxonomy strings:
- `"Projects"`: Goal-driven, deadline-bound initiatives.
- `"Areas"`: Ongoing spheres of standard maintenance and responsibility.
- `"Resources"`: Reference material, evergreen concepts, and domain knowledge.
- `"Archives"`: Inactive, retired, or historical reference items.

### 4.3 Wiki Markdown Note Frontmatter Contract
Every note in `wiki/**/*.md` must begin with valid YAML frontmatter formatted as follows:

```markdown
---
id: "c4b1e2a0-8f9d-4e1b-b2c3-9a8d7e6f5c4b"
title: "Modern RAG Architecture & Decoupled Pipelines"

tags: ["rag", "architecture", "vector-search"]
created_at: "2026-11-23T09:15:30.124Z"
updated_at: "2026-11-23T09:20:00.000Z"
summary: "High-signal 1-2 sentence core insight extracted from the source."
source_uri: "https://example.com/deep-dive-rag-architectures"

## 5. Frontend & UI Conventions (`public/`)

### 5.1 Technology Constraints
- **Zero Heavy Frameworks:** Do not introduce React, Vue, Svelte, or Webpack/Vite bundlers. Keep frontend execution pure: vanilla HTML5, modern CSS3, and ES6+ JavaScript (`app.js`).
- **CDN Scripts:** Use version-pinned, reputable CDN distributions for visualization libraries:
  ```html
  <script src="https://unpkg.com/vis-network/standalone/umd/vis-network.min.js"></script>
  ```

### 5.2 Category Palette Standards
Color assignments across the canvas, node borders, badges, and legend items must adhere to these exact hex values:

| Category | Primary Color | Border Color | Visual Meaning |
|---|---|---|---|
| **Projects** | `#F59E0B` (Amber-500) | `#D97706` (Amber-600) | Active, urgent, goal-driven |
| **Areas** | `#3B82F6` (Blue-500) | `#2563EB` (Blue-600) | Broad responsibility, continuous |
| **Resources** | `#10B981` (Emerald-500) | `#059669` (Emerald-600) | Evergreen assets, knowledge |
| **Archives** | `#6B7280` (Slate-500) | `#4B5563` (Slate-600) | Inactive, historical |

### 5.3 JavaScript Code Structure (`app.js`)
- **Strict Mode:** Always place `"use strict";` at the top of scripts.
- **State Encapsulation:** Store UI state in a single state object:
  ```javascript
  "use strict";

  const AppState = {
    network: null,
    graphData: { nodes: new vis.DataSet(), edges: new vis.DataSet() },
    activeFilter: "ALL",
    selectedNodeId: null,
    isSearching: false
  };
  ```
- **XSS Prevention:** Never use `element.innerHTML = rawNoteContent` without sanitizing input or using `textContent` for unescaped user inputs.

## 6. Serverless API Conventions (`api/`)

### 6.1 Handler Structure for Vercel Python
Vercel serverless functions in Python use `http.server.BaseHTTPRequestHandler`:

```python
import json
import logging
from http.server import BaseHTTPRequestHandler

logger = logging.getLogger("secondself.ask")

class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        try:
            content_length = int(self.headers.get("Content-Length", 0))
            if content_length == 0:
                self._send_response(400, {"error": "Missing request body"})
                return

            body = json.loads(self.rfile.read(content_length))
            question = body.get("question", "").strip()

            if not question:
                self._send_response(400, {"error": "Field 'question' is required."})
                return

            # Execute RAG query logic...
            result = {"answer": "...", "sources": [], "latency_ms": 650}
            self._send_response(200, result)

        except Exception as e:
            logger.error("Error processing ask request: %s", str(e), exc_info=True)
            self._send_response(500, {"error": "Internal server error"})

    def _send_response(self, status_code: int, data: dict):
        self.send_response(status_code)
        self.send_header("Content-Type", "application/json")
        self.send_header("Access-Control-Allow-Origin", "*")
        self.end_headers()
        self.wfile.write(json.dumps(data).encode("utf-8"))
```

### 6.2 Cold-Start Mitigation & Global Caching
Precomputed indices (`public/index.json`) must be cached in memory across warm serverless invocations:

```python
_CACHED_INDEX: dict | None = None

def get_index_data() -> dict:
    global _CACHED_INDEX
    if _CACHED_INDEX is None:
        with open("public/index.json", "r", encoding="utf-8") as f:
            _CACHED_INDEX = json.load(f)
    return _CACHED_INDEX
```

## 7. AI Prompt Engineering & LLM Conventions

### 7.1 Temperature & Model Settings
- **Groq Models:**
  - High-precision classification & RAG synthesis: `llama-3.3-70b-versatile`
  - High-throughput / test runs: `llama-3.1-8b-instant`
- **Temperature Configuration:**
  - PARA Classification (`classify.py`): `temperature = 0.1` (deterministic classification).
  - RAG Synthesis (`api/ask.py`): `temperature = 0.2` (factual grounding with minimal drift).

### 7.2 Structured Output Enforcement
LLM classification calls must enforce strict JSON responses. Always include:
1. System prompt requiring `{ "category": "...", "title": "...", "tags": [...], "summary": "...", "cleaned_markdown": "..." }`.
2. Groq `response_format={"type": "json_object"}` parameter.
3. Fallback schema validation with Pydantic.

### 7.3 Grounded Synthesis Citation Format
The synthesis prompt must instruct the model to explicitly tag citations:
```text
Every factual claim must cite its source note using [Note: <note_id>].
Do not cite sources not present in the provided context.
```

## 8. Git, Commit & Release Conventions

### 8.1 Conventional Commits
All commit messages must strictly follow the Conventional Commits specification:

```text
<type>(<scope>): <short imperative summary>

[optional body describing motivation and technical trade-offs]
```

#### Allowed Types
- `feat`: A new user-facing capability or script.
- `fix`: A bug fix in pipeline, physics, or API logic.
- `docs`: Documentation updates (`Architecture.md`, `README.md`, etc.).
- `refactor`: Code reorganization with zero behavior change.
- `perf`: Performance optimizations (e.g., vector dot product speeding).
- `test`: Adding or updating test cases.
- `chore`: Dependency updates, `.gitignore`, or configuration changes.

#### Allowed Scopes
- `(capture)`: Related to `capture.py` and raw extraction.
- `(classify)`: Related to `classify.py` and PARA prompt engineering.
- `(link)`: Related to `link.py`, vector embeddings, or wikilinks.
- `(graph)`: Related to `build_graph.py` and `graph.json`.
- `(ui)`: Related to `public/index.html`, `app.js`, `style.css`.
- `(api)`: Related to `api/ask.py` and serverless handling.
- `(deploy)`: Related to Vercel configuration, GitHub Actions, or deployment.

#### Examples
```bash
feat(capture): add PDF extraction adapter via pypdf
feat(classify): implement PARA categorization with Groq Llama 3
perf(link): vectorize cosine similarity with NumPy matrix multiplication
fix(ui): prevent physics instability during initial canvas stabilization
docs(arch): update serverless cold-start mitigation strategy
```

### 8.2 Deployment Trigger Discipline
Because Vercel is connected to GitHub for automatic continuous deployment, only push commits to `main` when:
1. `python link.py` and `python build_graph.py` have finished cleanly.
2. `public/graph.json` and `public/index.json` are validated and updated.
3. Local verification (`python ask.py "test question"`) passes without errors.

## 9. Security & Secrets Management Conventions

1. **Environment Variables:**
   - Secrets belong strictly in `.env` for local execution and in **Vercel Project Settings > Environment Variables** for cloud deployment.
   - Never commit `.env` to Git. Keep `.env.example` up to date with dummy placeholder values.
2. **API Key Pattern:**
   - Groq API keys follow the prefix `gsk_`.
   - Any script detecting a committed API key must fail immediately and alert the developer to revoke it.
3. **Data Sanitization:**
   - Ingested web URLs and files must be stripped of executable script tags (`<script>`, `<iframe>`) before writing to `raw/` or `wiki/`.
